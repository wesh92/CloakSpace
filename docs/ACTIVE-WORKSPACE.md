# Active scratchpad workspace

Showing the scratchpad activates a **monitor-local workspace**, even with no members. A black tint (default **36/255** uniform alpha) covers the work area on the monitor under the pointer, beneath the scratch windows. Set global or profile-local [`tint-opacity`](CONFIGURATION.md#tint-opacity) from 0.0 to 1.0 to change its strength; local overrides global, the last value in a scope wins, and changes require a restart. Zero uses a minimum native alpha of 1/255 to preserve hit testing and input shielding; 1.0 is fully opaque. This follows the existing monitor/work-area tiling convention; it is not a tint attached to one particular foreground HWND. The taskbar and other monitors are not covered.

The backdrop does not fade by default. To opt in, add `tint-fade-ms 180` at top level or inside a profile, outside any `never-elevate` block, then restart. [`tint-fade-ms N`](CONFIGURATION.md#tint-fade) takes one ASCII decimal integer from 0 to 500. The last value in each scope wins; imports are processed where they appear. A profile inherits the final global if it sets no local value, even if that global appears later or in an import. A local `tint-fade-ms 0` turns the fade off for that profile despite a nonzero global.

## Interaction

- Use the existing `scratch.toggle` binding or tray Show / hide command to enter and leave. With a nonzero fade duration, ordinary Show and Hide animate the backdrop only; member windows do not fade.
- Scratch members, their child controls and owner-linked dialogs remain interactive and above the backdrop. Clicking or scrolling the empty background does not click through to an underlying window.
- A narrowly scoped keyboard/mouse guard also consumes ordinary input addressed to windows actually beneath the backdrop, including foreground reactivation, both wheel axes and foreign mouse capture. It does not disable foreign windows, stop background application work, or suppress unrelated windows on other monitors or popups above the workspace.
- When empty, the backdrop provides a focus surface. Removing or closing the last member leaves the empty workspace active until Show / hide or Restore all is used.
- Release keys held at startup and finish any held-button drag/menu before entering. Entry can be refused rather than interrupting an existing mouse gesture. A consumed down retains its matching up even if the workspace hides or focus changes, so a background click or orphan key release is not replayed.
- During ordinary Hide the input shield stays active until native removal is confirmed. Only then is the workspace marked inactive and member Hide allowed to begin. A failed member operation after removal stays retryable without retaining a blocking backdrop. If a member stays visible or shows itself again while the workspace is inactive, CloakSpace attempts to undo its opacity changes without releasing the member.
- Restore all, normal exit, and failed-entry rollback cancel any fade and request native hide immediately, without waiting for animation. They still require native removal to be confirmed before proceeding with member operations.
- If removal times out or fails, the operation reports failure, retains the active state/member claims and skips those member waits. Let the surface thread recover, then retry Show / hide or Restore all. Delayed cleanup may remove the tint before the retry; `visible=1` conservatively remains until removal is acknowledged. This is not reported as successful restoration, including when empty.
- `--restore` exits nonzero on unconfirmed removal or member-release failure. Its status line appends `failed=1` for a failed control operation, even with `members=0`; `--status` is a query, not a cached last-operation result. Normal exit is refused until removal and releases succeed. Session-end cleanup is best effort; it cannot veto forced OS/process termination.
- Failed surface entry is cancelled and rollback is explicitly acknowledged. If setup failed after showing the tint and rollback is also unconfirmed, the core retains the conservative active/removal-retry state instead of reporting inactive or arranging members. A failed refresh follows the same acknowledgment/retry rules rather than starting member waits beneath an unconfirmed shield.

The independent surface thread maintains only its own Z-order/focus; it does not continuously retile or move scratch members. Its popup is deliberately **unowned**: a cross-thread HWND owner attaches input queues and can deadlock show/destroy while the host waits. The application explicitly joins the surface thread on cleanup. Generation-tagged requests prevent a timed-out entry from later leaving an orphan backdrop.

## Limits

This is ordinary desktop interaction shielding, **not a security boundary**. As with the existing hooks, Windows hook removal/timeouts, competing tools, secure desktops, higher-integrity targets and unusual raw/background input paths are not universally interceptable. Forced termination can leave scratchpad members hidden or with CloakSpace's opacity changes still applied. Use Restore all before exiting normally; a forced stop is not a recovery action. CloakSpace does not disable foreign windows. Actual multi-monitor/DPI and physical input compatibility still need operator testing.

## Verification

`bash build.sh test` and `build.cmd test` include `tests/test_overlay.c`. It captures only a disposable fixture rectangle: the inactive white control and the visibly uniform gray default tint, and checks native geometry, alpha/styles, hit testing, member Z-order and cleanup. Configured alpha is read back with `GetLayeredWindowAttributes` for defaults, 0.5, 1.0 and near-zero settings; native hit testing, guard callbacks and deactivation are checked for each. The real-executable host suite checks selected-profile/global precedence and zero opacity clamping at startup. It also observes a visible intermediate native alpha and then the configured endpoint on Show with a nonzero fade, and contrasts that with a local zero overriding the global. It does not assert exact frame timing. The overlay suite replays the production guard callbacks against disposable HWNDs for background typing, five mouse buttons, both wheel axes, capture, member/child/dialog interaction and paired releases. Fault injection covers hook/setup failure, startup-held keys, held mouse buttons, position failure and delayed activation cancellation.

The expanded core and real-executable host suites cover empty entry/hide/Restore all, retention of an active empty workspace, failure cleanup, real guard installation/removal, tray/control paths and normal exit. `tests/test_deactivation.c` additionally runs the actual core, native surface, host procedure and control client together: delayed removal, a stalled surface thread, native hide refusal, failed-entry/refused-rollback, empty/populated Restore, failure-bit/nonzero-CLI results, empty-exit refusal and successful retries. It asserts native visibility and production guard callbacks and counts member operations to catch waits while the shield persists. Snapshot publication is event-synchronized on each owner thread; a posted inspection after queued cleanup is the completion barrier, not invisibility alone. Only hooks/foreground/member operations are fixtures; faults are test-local, with no production debug option. **Callback replay is not synthesized OS input or end-to-end physical-input certification.** Automation sends no global user shortcuts and does not hide, disable or terminate an operator's application.

For manual verification, use disposable windows to check entry, hide, Restore all and normal exit on each monitor/DPI setup you use. Confirm that members and their dialogs remain interactive, the empty background does not click through, and other monitors remain usable. Physical input and installed-application compatibility are not established by callback replay alone.
